# Impact Intelligence — Known Limitations (MVP)

**Version:** Pilot phase (commit 7d7cf17)
**Date:** July 2026

This document states the known limitations of Impact Intelligence during the pilot phase. It helps set clear expectations with pilot schools and stakeholders.

---

## Product Limitations

### 1. Not a Full LMS (Learning Management System)

Impact Intelligence is an **analytics and reporting layer** on top of assessment data. It is not a full LMS. The following LMS features are **not included**:

- Curriculum planning and lesson scheduling
- Assignment submission and grading workflow
- Attendance tracking
- Timetable management
- Communication tools (announcements, messaging)

### 2. No Parent Portal

Parents cannot currently access learner performance data. The system is designed for teacher and school leadership use only. A parent portal is not planned for the MVP phase.

### 3. No Ministry Integration

Impact Intelligence does not connect to any Ministry of Education systems. Data cannot be automatically submitted to national or regional education databases. The Ministry-style demo dashboard is a **standalone preview**, not a live integration.

### 4. No Auto-Marking

Impact Intelligence does **not** mark assessments automatically. Teachers design and mark their own tests as usual. Marks must be entered manually into the system. The analytics engine processes the entered marks — it does not grade open-ended responses or scan answer sheets.

### 5. No RBAC / Multi-School Permissions

During the pilot phase:

- There is no role-based access control (RBAC) beyond the basic password gate
- Multiple schools use the same database — there are no per-school isolation boundaries
- Any authenticated user can see all schools' data

Full multi-tenant permissions are planned for production deployment.

---

## Technical Limitations

### 6. AI Summaries Are Advisory Only

The system includes optional AI-generated summaries (teacher summary, intervention plan, remedial lesson). These are **advisory only** and:

- Are generated by a third-party AI provider
- May contain inaccuracies or hallucinations
- Should be reviewed by the teacher before action
- Can be disabled if not needed

**The deterministic analytics (pass rates, topic performance, learner risk scores) are the source of truth** — they are calculated directly from marks with no AI involvement.

### 7. Single Assessment Analytics

The analytics engine calculates performance for one assessment at a time. There is no:

- Longitudinal tracking across multiple terms
- Term-over-term trend analysis
- Multi-subject aggregate performance

### 8. No Offline Mode

Impact Intelligence requires a live internet connection to the server. There is no offline mark entry or caching.

---

## Data Limitations

### 9. Learner Codes Only

During the pilot, learners are identified by codes (L001, L002). Full names are not required but can be added. This means:

- Reports refer to "Learner L001" rather than by name
- Teachers need their own class list to map codes to names

### 10. No Bulk Data Import

There is no CSV/XLSX import for marks or learners. All data must be entered through the web interface or API. For large cohorts, this is time-consuming.

### 11. Manual Question-Topic Mapping

Each question must be manually linked to a topic when setting up the assessment. There is no automatic topic detection or question bank.

---

## Deployment Limitations

### 12. Single Server

The current deployment uses a single server for frontend, API, and database. There is no:

- Load balancing
- Database replication
- Automated failover

### 13. No Standalone Domain Yet

Access is via `vault-lms.duckdns.org/impact`. A dedicated impact domain (`zimlearngraph-impact.duckdns.org`) is configured but not yet activated due to DNS setup.
