# Impact Intelligence — Known Limitations

This document describes the current limitations of the Impact Intelligence MVP. These are acknowledged and inform the product roadmap.

---

## Functional Limitations

### Not a Full LMS
Impact Intelligence is an assessment analytics module, not a full Learning Management System. It does not include:
- Lesson planning
- Assignment submission
- Gradebook across subjects
- Attendance tracking
- Timetabling
- Communication tools

### No Real Ministry Integration
The Ministry Demo dashboard shows aggregate data from the pilot school only. It is not connected to any real ministry data system. Future roadmap includes ministry-level data pipelines.

### No Parent Portal
Parents cannot view their child's performance. This is a future feature on the roadmap.

### No Auto-Marking
Impact Intelligence does not automatically mark assessments. Teachers must enter scores manually. Future roadmap may include scan-to-import for multiple-choice questions.

### Single School Scope
The current MVP is designed for single-school use. Multi-school administration and district-level aggregation are future features.

---

## AI Summary Limitations

### Advisory Only
AI summaries are generated by AI and are **advisory only**. The deterministic analytics (pass rate, class average, weak topics) are the source of truth. Teachers should always review the numbers before acting on AI recommendations.

### Optional Feature
AI summaries are optional. The core analytics dashboard works without any AI provider configured. If no AI provider is available, the message "AI summaries are unavailable. Assessment analytics are still available." is shown.

### No AI Performance Decisions
AI does not determine learner pass/fail, risk level, or intervention severity. These are all calculated deterministically from the marks entered. AI only provides explanatory text and suggested plans.

### Provider Dependent
AI summary quality depends on the configured AI provider and model. Different providers may produce different-quality summaries. The system hides provider/model details from the teacher UI.

---

## Data Limitations

### Learner Codes Recommended
The pilot uses learner codes (L001, L002) instead of full student names. This is intentional for privacy but means the system does not display learner names by default.

### Manual Data Entry
Marks must be entered manually. There is no bulk import from CSV or integration with existing school systems. The data template document describes the required format if manual entry is too slow.

### No Real-Time Updates
Dashboard data reflects the most recently saved marks. It does not update in real time — refresh the page to see new data.

---

## Export Limitations

### CSV Format
CSV exports use comma separators. Some regional Excel settings may require importing with explicit delimiter selection. UTF-8 encoding is used.

### PDF via Browser Print
The MVP uses browser "Print → Save as PDF" rather than server-side PDF generation. Print layout quality may vary by browser and OS. Chrome and Firefox produce the best results.

## Technical Limitations

### No Offline Mode
Impact Intelligence requires a network connection to the API server and SurrealDB database. Offline operation is not supported.

### No Mobile App
The interface is web-based and responsive but not optimized for mobile. Tablet use is acceptable; phone use is not recommended.

### Single Database
All data is stored in a single SurrealDB instance. Backup and disaster recovery procedures must be managed separately.

## Summary

Impact Intelligence MVP is a **teacher support tool**, not a replacement for any existing system. It turns assessment marks into actionable learning evidence. The analytics are deterministic and reliable. AI features are optional and advisory.

We are transparent about these limitations so schools can make informed decisions about pilot participation.
